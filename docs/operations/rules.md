## 設定ステータス管理

すべての設定項目に以下のラベルを付与する。

| ラベル | 意味 | 変更時のルール |
|--------|------|--------------|
| **[確定]** | 最終決定済み | 変更する場合は全ファイルの矛盾チェック必須。変更理由をコミットメッセージに記載 |
| **[有力案]** | 方向性は固まっている | 確定への昇格は自由。大幅な方向転換は矛盾チェック |
| **[未確定]** | 複数案あり | 自由に追加・変更可能。決定時に有力案→確定へ昇格 |

## ファイル命名規則

### ディレクトリ構成
```
docs/
├── overview.md              # 企画概要
├── world/                   # 世界観設定
│   ├── magic-system.md
│   ├── society.md
│   ├── outdoor-culture.md
│   └── （今後追加される世界観ファイル）
├── characters/              # キャラクター設定
│   ├── protagonist.md
│   └── （今後追加されるキャラクターファイル）
├── themes/                  # テーマ構造
│   └── core-themes.md
├── plot/                    # プロット・構成
│   ├── open-questions.md
│   ├── story-seeds.md
│   └── （今後追加されるプロットファイル）
├── operations/              # 運用ルール
│   └── rules.md
└── episodes/                # 各話（今後作成）
    ├── ep01-outline.md
    ├── ep01-draft.md
    └── ...
```

### 命名規則
- ファイル名は英語のケバブケース（`magic-system.md`）
- キャラクターファイルは `characters/{名前 or 役割}.md`
- エピソードファイルは `episodes/ep{番号}-{種別}.md`
  - 種別: `outline`（構成）、`draft`（草稿）、`final`（最終稿）

## 設定変更ルール

### 新しい設定を追加するとき
1. どのファイルに反映するかを明示する
2. 既存の[確定]設定と矛盾しないかチェックする
3. 矛盾する場合は、黙って変更せず警告する
4. 新設定のステータスラベルを付与する

### 確定設定を変更するとき
1. 変更理由を明示する
2. 影響を受けるファイルを全て列挙する
3. 矛盾が生じる箇所を修正する
4. コミットメッセージに「[設定変更]」プレフィックスをつける

### 未確定事項を決定するとき
1. `open-questions.md` の該当項目を更新する
2. 関連ファイルに[確定]として反映する
3. 決定理由を簡潔に記録する

## 新アイデアの整理ルール

新しいアイデアが出たら、必ず以下の3区分で整理する。

1. **確定案** — 既存設定と整合し、採用する案
2. **保留案** — まだ決めていない。検討の余地あり
3. **別案** — 魅力はあるが現時点では採用しない案（理由を記載して保存）

## コミットメッセージ規則

```
[カテゴリ] 簡潔な説明

カテゴリ:
- [世界観] 世界設定の追加・変更
- [キャラ] キャラクター設定の追加・変更
- [プロット] プロット・エピソード関連
- [テーマ] テーマ構造の変更
- [運用] 運用ルール・構成の変更
- [設定変更] 確定設定の変更（影響範囲を本文に記載）
- [草稿] エピソードの草稿
```
